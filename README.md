# 1C Comment Hotkeys Utility

Десктопная утилита для Windows, которая помогает разработчику быстро и единообразно комментировать код по шаблонам.

## Описание

Программа работает в фоне и автоматизирует шаблонное комментирование кода:
1. Разработчик выделяет фрагмент кода.
2. Нажимает глобальную горячую клавишу.
3. Выбирает нужный шаблон комментария.
4. Утилита вставляет готовый комментарий с подстановкой макросов (дата/время/автор/Jira) и форматированием.

Шаблон может содержать блок `{@llm}...{@end}` — его содержимое (например, промпт с выделенным кодом) отправляется в OpenAI-совместимый LLM, а ответ модели подставляется в результат. Так делаются документирующие комментарии к методам, рефакторинг или локальное код-ревью по горячей клавише.

Это снижает ручную рутину, ускоряет оформление изменений и делает комментарии в команде более единообразными.

## Использование

1. После запуска программа сворачивается в системный трей
2. В меню трея доступна команда `Обновить источники` для принудительного обновления Jira-кэша и команда `Сбросить кэш ответов LLM` (см. «Блочная директива `llm`»)
3. В окне настроек можно изменить глобальный хоткей (по умолчанию `Ctrl+=`) и сохранить
4. Пустая глобальная комбинация допускается: в этом режиме работает только быстрый хоткей у шаблонов
5. Нажмите глобальный хоткей
6. В открывшемся диалоге выберите нужный комментарий:
   - Используйте поиск для фильтрации
   - Двойной клик или кнопка "OK" для выбора
   - ESC или "Отмена" для отмены
7. В главном окне можно менять порядок комментариев перетаскиванием строк таблицы
8. Новый порядок применяется в памяти сразу, но записывается в файл только по кнопке `Сохранить`
9. Если комментарий привязан к Jira-источнику, откроется диалог выбора задачи:
   - При устаревшем кэше и неуспешном обновлении диалог показывается всегда, даже если задача одна
   - Кнопка `Обновить` выполняет асинхронный запрос к Jira и обновляет список без зависания UI
10. Выделенный текст будет автоматически модифицирован согласно шаблону
11. Если в шаблоне есть директива `{@llm}...{@end}`, содержимое блока отправляется в выбранный для комментария профиль LLM (окно `Профили LLM`); на время запроса показывается окно ожидания с кнопкой `Отмена`, результат вставляется после ответа модели

## Конфигурация

### Файлы конфигурации

Конфигурационные файлы хранятся в:
- **Windows (обычная установка Python):** `%APPDATA%\1CCommentHotkeys\`
- **Windows (Python из Microsoft Store):** `%APPDATA%\1CCommentHotkeys\` (при первом запуске выполняется перенос из legacy-пути в `LocalCache\Roaming`, если данные там уже есть)

Если файл `comments.json`, `jira_sources.json` или `llm_profiles.json` поврежден и не читается, приложение не перезаписывает его: файл переименовывается в `<имя>.broken-<дата-время>`, показывается предупреждение, и работа продолжается с пустым списком (для комментариев — с набором по умолчанию).

### Файл config.json

```json
{
  "hotkeys": [
    {
      "combination": "ctrl+=",
      "action": "show_comment_dialog"
    }
  ],
  "ui": {
    "start_minimized": true,
    "log_to_file": false,
    "author": "AUTHOR"
  },
  "security": {
    "encrypt_tokens": true
  }
}
```

Горячая клавиша и UI-настройки читаются из `config.json`.
`log_to_file=true` включает запись логов в файл `app.log` в каталоге настроек.
`security.encrypt_tokens` (по умолчанию `true`, флажок «Шифровать токены и ключи» в главном окне) — хранить токены Jira-источников и ключи API профилей LLM зашифрованными через Windows DPAPI. При отключении они записываются открытым текстом.
Запись `config.json` выполняется атомарно (через временный файл и `os.replace`) для снижения риска повреждения при аварийном завершении.

### Файл comments.json

Содержит список шаблонов комментариев. При первом запуске (или если файл поврежден) создается набор по умолчанию: `Код добавлен`, `Код удален`, `Метод добавлен`, `Коммит`, `Метаданные`, `Номер задачи`, `Код изменен`, `Расширение - Вставка`, `Расширение - Удаление`, `Расширение - Изменение` и `Документирующий комментарий` (последний использует `{@llm}` — чтобы он заработал, создайте профиль LLM и выберите его в шаблоне).

Пример файла (промпт шаблона `Документирующий комментарий` сокращен; в наборе по умолчанию он подробно описывает правила оформления по стандартам разработки 1С):

```json
[
  {
    "name": "Код добавлен",
    "template": "{@line_limit max=120 mode=wrap suffix=\"// \"}// + {author}. {datetime}. [{issue_key}] {issue_summary}{@end}\n{text}\n// - {author}. {datetime}.",
    "hotkey": "ctrl+alt+1",
    "source": "Мой Jira фильтр",
    "hidden": false
  },
  {
    "name": "Код удален",
    "template": "{@line_limit max=120 mode=wrap suffix=\"// \"}// + {author}. {datetime}. [{issue_key}] {issue_summary}{@end}\n{text|prefix=\"//\"}\n// - {author}. {datetime}."
  },
  {
    "name": "Код изменен",
    "template": "{@line_limit max=120 mode=wrap suffix=\"// \"}// + {author}. {datetime}. [{issue_key}] {issue_summary}{@end}\n{text|prefix=\"//\"}\n{text}\n// - {author}. {datetime}."
  },
  {
    "name": "Метод добавлен",
    "template": "{@line_limit max=120 mode=wrap suffix=\"// \"}// {author}. {datetime}. [{issue_key}] {issue_summary}{@end}"
  },
  {
    "name": "Коммит",
    "template": "[{issue_key}] {issue_summary}"
  },
  {
    "name": "Метаданные",
    "template": "// {author}. {date}. {issue_key}."
  },
  {
    "name": "Номер задачи",
    "template": "{issue_key}"
  },
  {
    "name": "Расширение - Изменение",
    "template": "#Удаление\n{text}\n#КонецУдаления\n#Вставка\n{text}\n#КонецВставки"
  },
  {
    "name": "Документирующий комментарий",
    "template": "{@line_limit max=120 mode=wrap suffix=\"// \"}// {author}. {datetime}. [{issue_key}] {issue_summary}{@end}\n{@llm}\nПодготовь документирующий комментарий для процедуры или функции на встроенном языке 1С:Предприятие (BSL) по стандартам разработки 1С.\n...\nПодготовь документирующий комментарий для:\n{text}\n{@end}\n{text}",
    "source": "Мой Jira фильтр",
    "llm_profile": "OpenAI"
  }
]
```

`hotkey` (опционально) задаёт быструю вставку конкретного комментария без диалога выбора.  
`source` (опционально) хранит название Jira-источника для комментария.
`hidden` (опционально) скрывает комментарий из диалога при нажатии глобальной горячей клавиши.
`llm_profile` (опционально) — название профиля LLM из `llm_profiles.json`, в который отправляются запросы директивы `{@llm}` этого шаблона.

### Файл jira_sources.json

Содержит источники Jira для комментариев:

```json
[
  {
    "name": "Мой Jira фильтр",
    "url": "https://your-domain.atlassian.net/issues/?jql=project%20%3D%20PROJECT%20ORDER%20BY%20updated%20DESC",
    "token": "dpapi:AQAAANCMnd8BFdERjHoAwE/Cl+s...",
    "ttl_minutes": 5,
    "timeout_seconds": 2,
    "auto_refresh": false
  }
]
```

Хранение токена:
- По умолчанию токен шифруется через Windows DPAPI и хранится в виде `dpapi:<base64>`. Расшифровать его может только та же учетная запись Windows на той же машине. Шифрование отключается флажком «Шифровать токены и ключи» в главном окне (`security.encrypt_tokens` в `config.json`) — тогда токены хранятся открытым текстом.
- Файл автоматически приводится к текущей настройке при запуске и при сохранении настроек: открытый токен (например, записанный вручную или из старой версии) шифруется, если шифрование включено; зашифрованный расшифровывается в открытый текст, если выключено.
- Если файл скопирован от другого пользователя, токены расшифровать не удастся — приложение покажет предупреждение, токены нужно ввести заново в окне `Источники`.
- В окне `Источники` токены по умолчанию скрыты; флажок `Показать токены` раскрывает их.

Важно для подстановки задач Jira:
- Нужно создать источник в окне `Источники` (название, ссылка на Jira-фильтр, токен).
- В нужном шаблоне комментария в поле `Источник` выбрать этот источник.
- Только при таком связывании источника и шаблона в комментарий будут подставляться `{issue_key}` и `{issue_summary}`.

Требование к ссылке источника:
- Ссылка должна вести на настроенный фильтр Jira с нужными задачами.
- В URL обязательно должен присутствовать параметр `jql` (именно он используется для запроса списка задач).

Настройки источника:
- `ttl_minutes` (мин) — время жизни кэша. `0` отключает кэш, `-1` хранит кэш без срока. По умолчанию `5`.
- `timeout_seconds` (сек) — таймаут запросов к Jira. Минимум `1`. По умолчанию `2`.
- `auto_refresh` — включить периодическое автообновление кэша для источника.

Поведение автообновления:
- Источник участвует в автообновлении только если `auto_refresh=true` и `ttl_minutes > 0`.
- При устаревании кэша запускается обновление источника в фоне.
- Если пользователь не выполнял действий в приложении более 60 минут, автообновление временно приостанавливается для всех источников.

### Файл llm_profiles.json

Содержит профили подключения к LLM для директивы `{@llm}` в шаблонах:

```json
[
  {
    "name": "OpenAI",
    "base_url": "https://api.openai.com/v1",
    "model": "gpt-4.1-mini",
    "api_key": "dpapi:AQAAANCMnd8BFdERjHoAwE/Cl+s...",
    "timeout_seconds": 60,
    "temperature": 0.2
  },
  {
    "name": "Ollama",
    "base_url": "http://localhost:11434/v1",
    "model": "qwen2.5-coder:7b",
    "api_key": "",
    "timeout_seconds": 120,
    "temperature": null
  }
]
```

Поддерживается любой OpenAI-совместимый Chat Completions API: к `base_url` добавляется `/chat/completions`, запрос — `POST` с одним `user`-сообщением, ответ читается из `choices[0].message.content`. Стриминг не используется.

Поля профиля:
- `name` — название, по нему профиль выбирается в настройках комментария (поле `Профиль LLM`).
- `base_url` — корень API (`https://api.openai.com/v1`, `http://localhost:11434/v1` для Ollama, адрес корпоративного прокси и т.п.).
- `model` — идентификатор модели.
- `api_key` — ключ API; передается в заголовке `Authorization: Bearer`. Может быть пустым (локальные серверы). Хранится так же, как токены Jira: зашифрованным через DPAPI при включенной настройке `security.encrypt_tokens`, иначе открытым текстом; файл приводится к текущей настройке при запуске и при сохранении настроек. В окне `Профили LLM` ключи скрыты, флажок `Показать ключи` раскрывает их.
- `timeout_seconds` — таймаут ожидания ответа (от 1 до 600, по умолчанию 60).
- `temperature` — от 0 до 2; `null` (пустое поле в окне) — параметр не передается и действует умолчание провайдера. Часть моделей принимает только значение по умолчанию.

Важно:
- Содержимое блока `{@llm}` вместе с выделенным текстом (кодом) отправляется на адрес профиля. Используйте только те endpoint'ы, которым доверяете код.
- Ключ API не попадает в лог; текст промпта и ответа тоже не логируются, только их длины.

### Файл jira_issues_cache.json

Содержит кэш задач Jira по источникам и время последнего обновления.

Запись файла выполняется атомарно (через временный файл и `os.replace`), чтобы уменьшить риск потери/повреждения данных при сбоях питания или shutdown.

### Файл jira_last_issue.json

Содержит последнюю выбранную задачу (`issue_key`) для каждого источника Jira.

Используется, чтобы в диалоге выбора задач последняя выбранная задача автоматически поднималась в начало списка.

## Макросы в шаблонах

Поддерживаемые макросы:
- `{text}` - выделенный текст
- `{date}` - текущая дата в формате `dd.MM.yyyy`
- `{time}` - текущее время в формате `HH:mm`
- `{datetime}` - дата и время в формате `dd.MM.yyyy HH:mm`
- `{author}` - автор из поля `Автор` в главном окне
- `{issue_key}` - ключ задачи Jira (если выбрана задача)
- `{issue_summary}` - краткое описание задачи Jira

## Расширенный синтаксис шаблонов

В шаблонах поддерживаются:
- обычные макросы (`{text}`, `{date}` и т.д.)
- модификаторы макросов (`{text|...}`)
- блочные директивы (`{@...} ... {@end}`)

Директиву блока (`{@...}` или `{@end}`), записанную на отдельной строке, можно
считать разметкой: сама эта строка в результат не попадает, лишних пустых строк
не появляется. Открывающая директива забирает перевод строки после себя,
закрывающая — перевод строки перед собой, а перевод строки после `{@end}`
остается снаружи блока. Поэтому шаблоны

```text
{@line_limit max=120 mode=wrap suffix="// "}// {author}. {datetime}{@end}
{text}
```

и

```text
{@line_limit max=120 mode=wrap suffix="// "}
// {author}. {datetime}
{@end}
{text}
```

дают одинаковый результат. Так же можно вкладывать блоки друг в друга, каждый
тег на своей строке.

### Модификатор `prefix` для `{text}`

Формат:
- `{text|prefix="..."}`

Поведение:
- Префикс добавляется к каждой **непустой** строке значения `{text}`.
- Пустые строки остаются пустыми.
- При наличии отступов префикс занимает место внутри отступа, чтобы код оставался на той же "колонке".

Пример:

```text
{text|prefix="// "}
```

Если выделенный текст:

```text
line 1

line 2
```

Результат:

```text
// line 1

// line 2
```

### Блочная директива `line_limit`

Формат:
- `{@line_limit max=120 mode=wrap suffix="// "}`
- `...текст и/или макросы внутри блока...`
- `{@end}`

Параметры:
- `max` - максимальная длина строки в символах (целое число, `<= 0` отключает ограничение).
- `mode` - режим обработки. Сейчас поддерживается `wrap` (перенос по словам).
- `suffix` - префикс, который добавляется к продолжению перенесенной строки.

Важно:
- Ограничение применяется **только к содержимому внутри блока**.
- Это позволяет, например, ограничивать длину заголовка комментария и не трогать `{text}` с кодом.
- Перенос выполняется по пробелам; длинные слова без пробелов не разрываются.

Пример выборочного применения:

```text
{@line_limit max=120 mode=wrap suffix="// "}
// + {author}. {datetime}. [{issue_key}] {issue_summary}
{@end}
{text}
// - {author}. {datetime}.
```

В этом примере:
- ограничивается только первая строка с задачей,
- `{text}` вставляется в исходном виде,
- `suffix="// "` добавляется к строкам-продолжениям при переносе.

### Блочная директива `llm`

Формат:
- `{@llm}`
- `...промпт: текст и/или макросы...`
- `{@end}`

Поведение:
- Содержимое блока сначала рендерится как обычная часть шаблона (то есть `{text}`, `{issue_summary}` и другие макросы внутри промпта подставляются), затем отправляется одним `user`-сообщением в профиль LLM, выбранный в поле `Профиль LLM` комментария. Ответ модели подставляется вместо блока.
- По умолчанию из ответа убираются обрамляющие markdown-ограждения кода (```` ``` ````) и пробелы/переводы строк по краям, поэтому переводами строк вокруг результата управляет сам шаблон. Параметр `raw=true` (`{@llm raw=true}`) отключает эту обработку.
- Несколько блоков `{@llm}` в одном шаблоне выполняются последовательно, все — в один профиль.
- Директиву можно вкладывать в `{@line_limit}` и наоборот.
- Последние ответы модели запоминаются в памяти (до 8 штук; на диск не пишутся, при выходе из программы теряются). Если тот же промпт уже отправлялся в профиль с теми же адресом, моделью и температурой, ответ берется из кэша без запроса. Промпт включает выделенный текст и шаблон, поэтому повторный вызов того же шаблона на том же коде (например, если вставка не удалась) выполняется мгновенно и без окна ожидания. Макросы вне блока (`{datetime}`, задача Jira) при этом подставляются заново. Ответ, пришедший уже после нажатия `Отмена`, тоже попадает в кэш. Чтобы получить от модели новый вариант для того же кода, выберите в меню трея `Сбросить кэш ответов LLM`.

На время запроса показывается окно ожидания с кнопкой `Отмена`; повторные нажатия горячих клавиш в это время игнорируются. Буфер обмена на время ожидания возвращается в исходное состояние. При ошибке (нет профиля, таймаут, HTTP-ошибка, пустой ответ) ничего не вставляется — выделение в редакторе остается как было, а причина показывается в сообщении. Если за время ожидания фокус ушел в другое окно, результат не вставляется вслепую, а копируется в буфер обмена с уведомлением.

Пример — документирующий комментарий метода 1С:

```text
{@line_limit max=120 mode=wrap suffix="// "}// {author}. {datetime}. [{issue_key}] {issue_summary}{@end}
{@llm}
Сформируй документирующий комментарий метода в строгом формате:
// <Краткое описание 1-2 предложения>
// Параметры:
//   <ИмяПараметра> - <Типы параметра> - <Краткое описание параметра>
//

Если это функция, добавь
// Возвращаемое значение:
//   <Типы возвращаемого значения> - Краткое описание

Отвечай только комментарием, без пояснений.

Метод:
{text}
{@end}
{text}
```

Для выделенного метода

```bsl
Процедура ПриПолученииСвойствРегистра(ИмяРегистра, СтруктураОписанияРегистра) Экспорт
	ПлановыеНачисленияСотрудников.ПриПолученииСвойствРегистраВторичныхДанных(ИмяРегистра, СтруктураОписанияРегистра);
КонецПроцедуры
```

результат будет примерно таким:

```bsl
// Автор. 28.07.2023 11:59. [TASK-123] Исправление ошибки
// Вызывается при получении свойств регистра
// Параметры:
//   ИмяРегистра - Строка - Имя регистра
//   СтруктураОписанияРегистра - Структура - Описание регистра
//
Процедура ПриПолученииСвойствРегистра(ИмяРегистра, СтруктураОписанияРегистра) Экспорт
	ПлановыеНачисленияСотрудников.ПриПолученииСвойствРегистраВторичныхДанных(ИмяРегистра, СтруктураОписанияРегистра);
КонецПроцедуры
```

Тем же способом можно делать шаблоны для рефакторинга (`{@llm}Перепиши метод ...{text}{@end}` без `{text}` после блока — результат заменит выделение) или локального код-ревью (`{text}` после блока, ответ модели — в виде комментария перед кодом).
